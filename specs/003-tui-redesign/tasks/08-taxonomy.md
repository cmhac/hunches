# 08 — Stage 3 Taxonomy and prompt: context turn, mode select, structured view and edit

Spec: D4, D5, D12 (the version hook is task 17). Handoff: `design/README.md` §5 "3 Taxonomy and prompt"; `design/BACKEND_CHANGES.md` §1, §4 (Taxonomy), §5; mock `ui_kits/tui-rail/Taxonomy.jsx` (it carries the exact message bodies and summaries); states `taxonomy/start`, `taxonomy/ready`, `taxonomy/context-open`, `taxonomy/context-updated`, `taxonomy/context-updated-open`, `taxonomy/drafted`, `taxonomy/edit-labels`, `taxonomy/edit-labels-invalid`, `taxonomy/edit-prompt`, `taxonomy/mode-open`, `taxonomy/mode-changed`, `taxonomy/edits-sent`, `taxonomy/edits-sent-open`, `taxonomy/tool-open`, `taxonomy/confirm`. `[behaviour]` + `[backend]`. File: `screens/taxonomy.py`. The largest UI task; consider doing it in the three commits-worth of steps below even though it lands as one commit.

## Goal
The assistant starts with the context the user has and stays in sync; the user edits labels, mode and prompt through structured views with explicit Save/Discard; nothing is written per keystroke.

## Do

### A. Context turn (BACKEND §1)
- **Inputs.** `files.load_chat("brief")` (user and assistant text only; tool calls collapsed to one line each; cap at the last 40 turns and truncate long tool arguments, visibly: "… 7 more"); `candidates.read_seeds()` with **items won** = `Counter(r["best_seed"])` over `candidates.jsonl` (counts sum to the candidate total); search summary (total at or above `candidates.FLOOR` and `candidates.band_counts`).
- **Digest and meta.** `digest = sha256(json([seeds, text of candidates.jsonl]))`. Persist to `.hunches/chat/taxonomy.meta.json`: `{"context_digest", "sent_at", "seeds", "n_candidates", "items_won"}` (spec data table). Stage screens are rebuilt on every `goto_stage`, so check on every mount: **no history** → send the initial context; **history and digest differs** → send an UPDATED context; equal → nothing. Write the meta only after the context turn has been appended and the reply completed (a half-sent context must not claim it was sent).
- **Messages.** Initial body sections `# Brief conversation`, `# Seeds and results (items won)`, `# Search`, `# Instructions` ("Reply in two or three sentences: where things stand (how many seeds, how many candidates, which seed found the most), and that you are ready to start building the taxonomy. Then begin the interview. Draft the prompt from the seeds and the best matches as the answers come in."). Summary line `Context · N seeds · M candidates`. Update body: `# What changed` (seeds added/removed/edited with `+`/`-` lines; `candidates: before → after`), new items won, instructions "Reply in one or two sentences: what changed and whether it affects the conversation so far. Then continue where you left off."; summary `Seeds changed · M candidates (+Δ)`. Send through `ChatPanel.send_context(..., "context"|"update", summary)` (task 03). Pure builders `initial_context()` / `update_context(old, new)` live in `taxonomy.py` for testing.
- **Guards.** Seeds empty or `candidates.jsonl` missing: skip the context turn (the old behaviour, instructions only). Changing the assistant model in Project settings rebuilds the screen with the new model; history replays as is.
- **Instructions.** Keep `INSTRUCTIONS`. Drop the `brief.md` and random-sample parts of `build_instructions()` (remove it and the `random` import; keep `brief.md` the file). Add `@agent.instructions` returning the current seeds, the current taxonomy (mode + labels) and prompt text, read from the screen's live state; when a mode is chosen add "The user chose mode X; do not ask about it again." Update `INSTRUCTIONS`: the mode is the user's choice in the UI, not a question for the agent.

### B. Labels panel and mode select (BACKEND §4–5)
- **Read view.** Title "Labels", subtitle mode and count. A compact `Select` captioned `mode` ("One label per item" / "Several labels per item") is **always** at the top, including before any labels exist (blank until chosen when there is no `taxonomy.yaml`). `m` opens it. One row per label: `label_tag(...)` ■ name, description muted; a fixed last row `off_topic` marked "built in". Button **Edit labels  e**.
- **Changing the mode enters Labels edit mode** with the new mode in the draft; Save commits it; it is recorded as a mode edit.
- **Edit mode.** Mode `Select`; one row per label with name and description `Input`s and a delete control; **Add label**. All edits stay in a screen-held draft. Buttons **Save  ^s** and **Discard  Esc**; subtitle badge `EDITING`, becoming `UNSAVED` once the draft differs from the file. Save is disabled while the draft is unchanged **or invalid**; invalid = `files.Taxonomy.model_validate` fails or there are no labels; show the first line of the message to the right of the buttons and mark the offending row with a red left bar. `ctrl+s` and `esc` via screen bindings active only in edit mode (`check_action`).

### C. Prompt panel
- **Read view.** Title "Prompt"; render `prompt.md` with `textual.widgets.Markdown` (primary h1, bold h2, bullets; style the component classes in `hunches.tcss`; if the match is poor, build the view from `Static` rows as the mock does). Button **Edit prompt  e**.
- **Edit mode.** A `TextArea` (markdown, line numbers, `theme.editor`) with **Save  ^s** / **Discard  Esc**, `EDITING` → `UNSAVED` badge.

### D. Shared rules
- Only one panel is in edit mode. While one is, the other panel and Approve are `disabled` and `F2` does nothing. Keys `e` act on the focused panel.
- **Writes only on Save:** `files.write_taxonomy(...)` / `files.write_text("prompt.md", ...)`. Delete `on_text_area_changed` and its per-keystroke writes.
- **Agent writes while editing (BACKEND §4).** `write_taxonomy` / `write_prompt`: panel not in edit mode → write the file, refresh the panel and tag it **UPDATED BY ASSISTANT** (info badge) until the user next interacts with it or the next agent turn starts; panel in edit mode → do **not** write; return `Not written: the user is editing the taxonomy. Ask them to save or discard first.` (and "…the prompt…" for the prompt). Keep the existing validation ("Rejected, nothing written: …").
- **Edit recording (BACKEND §5)** on every Save, via `chat.record(...)` (no model call), summary and body per the mock: `Labels: layoff_fear description` (per-label was/now, adds, deletes), `Mode: one label → several labels`, `Prompt: N lines changed` (unified diff via `tune.diff`-style helper; `# Current prompt` holds the **full** text because the agent will be asked to revise it), plus `# Current taxonomy`. Drafts and Discard record nothing. After recording, update `chat/taxonomy.meta.json`'s snapshot so the next mount does not send an UPDATED line for the same change (seeds/candidates unchanged, so the digest is unaffected; only mind that the meta is not rewritten with stale seeds).
- **Approve.** A primary **Approve taxonomy and prompt  F2** button under the panels, disabled until both a valid taxonomy (≥1 label) and a non-empty prompt exist, or while editing. Remove the "Cannot approve…" status lines; keep the guards as silent no-ops in `action_approve`. Confirm text exactly: "Approve taxonomy (single, 3 labels) and prompt, and start labelling?" (mode word and label count from the taxonomy). `save_target` (default target metric from `metrics.default_target_metric`) is unchanged.
- Footer: view mode shows `e Edit`, `F2 Approve`; edit mode shows `^s Save`, `esc Discard`.

## Tests
- Context: builders produce the exact section headers and the hand-counted items-won (sum equals candidate count); transcript cap and "… N more" truncation; digest stable for equal inputs, different when a seed or a candidates row changes; mount with no history sends one context turn and writes the meta after the reply; mount with an unchanged digest sends nothing; changed seeds send one UPDATED turn; empty seeds skip. Count model calls with `FunctionModel`.
- Instructions function includes seeds, taxonomy, prompt and the mode sentence.
- Edit flows (Pilot): `e` → inputs; edit a description → UNSAVED, Save enabled; `ctrl+s` writes `taxonomy.yaml` and appends one `edit` request, zero model calls; Esc discards and writes nothing; invalid draft (a label named `off_topic`) → Save disabled with the message; changing the mode via `m` enters edit mode; empty-labels draft → Save disabled "at least one label is required".
- One panel at a time: while Labels editing, Prompt panel and Approve are disabled, F2 no-op.
- Agent write guard: tool returns "Not written…" while editing, writes and tags UPDATED BY ASSISTANT otherwise.
- Approve button disabled with no prompt; confirm text exact.
- Breakers in `tests/test_taxonomy_screen.py`: `#taxonomy`/`#prompt` TextAreas, `#status`, `Cannot approve`, per-keystroke write tests, `build_instructions`.
